## Architecture
Multi-site Gatsby project. `SITE` env var (default: `ncyimby`) selects which site to build.
- `sites/<id>/config.ts` holds all site-specific values (branding, nav links, feature flags)
- `sites/<id>/tokens/` holds DTCG design tokens (primitives + semantic)
- `sites/<id>/theme.css` is auto-generated from tokens (do not edit directly)
- `sites/<id>/DESIGN.md` holds visual direction and design philosophy
- `sites/<id>/aliases.json` maps legacy CSS variable names to new token names
- `@/site` webpack alias resolves to `sites/<SITE>/` at build time
- Dev: `SITE=stoside yarn dev` or `SITE=ncyimby yarn dev`
- Build: `SITE=stoside gatsby build`

## Workflow
After completing a code change, commit and push without asking. Deployment pipeline is attached to this repo.

## Design System

All UI uses the design token system. Read the active site's `DESIGN.md` for visual direction before any UI work.

### Rules
- All colors via CSS custom properties from `sites/<SITE>/theme.css`. Never hardcode hex, rgb, hsl, or named CSS colors.
- All spacing via `--space-*` tokens. Never use arbitrary px/rem values for margin, padding, or gap.
- All font sizes via `--font-size-*` tokens.
- All font families via `--font-display`, `--font-body`, `--font-mono` tokens.
- All border radii via `--radius-*` tokens.
- Dashboard data viz colors via `--dash-*` tokens (accent, positive, negative, neutral, surface). Stoside only.
- Use semantic token names (`--bg-primary`, `--text-primary`, `--accent-primary`) in new code, not legacy names (`--bg`, `--text`, `--accent`) or primitive names (`--color-warm-100`).
- Alpha tints use `color-mix(in srgb, var(--token) N%, transparent)`, not rgba or opacity hacks.

### Component reuse
- Read existing components before creating new ones. Extend or wrap; don't duplicate.
- `Vis/` components are thin adapters over `Dashboard/` components. Never duplicate Dashboard logic into Vis.
- Dashboard section headers use `SectionHeading` component, not inline markup.
- Chart y-axis repositioning uses `chart-utils.ts` `repositionYAxis()`.
- Pagination uses `usePagination` hook + shared `Pagination` component.
- New components follow existing patterns (same file structure, same prop conventions, same naming).

### Data viz palettes
- Categorical: `CATEGORICAL` from `Dashboard/palette.ts`.
- Sequential blues: `BLUE_RAMP` (flat array) or `SEQUENTIAL_BLUES` (with breakpoints) from `color-scales.ts`.
- Don't create ad-hoc color arrays. Use or extend the existing palettes.

### Token files (per site, in `sites/<id>/`)
- Primitives: `tokens/primitives.json` (raw values, named by what they are)
- Semantic: `tokens/semantic.json` (role-based references, named by what they do)
- Built CSS: `theme.css` (generated by `npm run build:tokens`, do not edit)
- Visual direction: `DESIGN.md`
- Legacy aliases: `aliases.json` (maps old var names to new; remove after migration)
